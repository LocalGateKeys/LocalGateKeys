# LocalGateKeys iOS

`LGKCore/` is the Swift package with the sync, crypto and LAN logic shared by the iPhone and Mac apps and their extensions.

## Tests

```
cd ios/LGKCore
swift test
```

Test vectors are the desktop's `tests/vectors/sync/` (found from `#filePath` by `Tests/LGKCoreTests/Support/Vectors.swift`).
The vectors win over any Swift behaviour. Tests fail, never skip, when vectors are missing. The Argon2id tests run
production parameters (128 MiB / 4 passes / 4 lanes) and take a few seconds each.

## App (Xcode project)

The project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`; the
`.xcodeproj` is not committed. Regenerate after cloning and after any change to `project.yml`:

```
cd ios
xcodegen generate
```

Targets: `LocalGateKeys` (app), `AutoFill` (credential provider extension), `SafariSave` (Safari Web Extension), `AppShared` (framework that links
LGKCore and re-exports it), `AppSharedTests`, `AutoFillTests` (the extension's matcher, unlock-then-fill flow and identity refresh, unhosted),
`LocalGateKeysTests` (app view models, hosted in the app), `LocalGateKeysWatch` (the Apple Watch app with the
pinned 2FA codes, sources under `Watch/`, embedded in the iPhone app) and `LocalGateKeysWatchTests` (its own scheme). AutoFill matching uses the desktop's
`src/localvault/assets/public_suffix_list.dat`, bundled into the app and the extension by project.yml. Run the app tests:

```
xcodebuild test -project ios/LocalGateKeys.xcodeproj -scheme LocalGateKeys \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' CODE_SIGNING_ALLOWED=NO
```

Mac targets (macOS 14+, same version train as the iPhone app): `LocalGateKeysMac` (app, sources under `Mac/`,
sharing some model files with `App/`), `AutoFillMac` (credential provider extension), `SafariMac` (Safari Web
Extension), `AppSharedMac` (the AppShared sources built for macOS), `LocalGateKeysMacTests` (the app's sources
compiled straight in, unhosted). Run the Mac tests:

```
xcodebuild test -project ios/LocalGateKeys.xcodeproj -scheme LocalGateKeysMac \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO
```

[phc-winner-argon2](https://github.com/P-H-C/phc-winner-argon2) at commit `f57e61e19229e23c4445b85494dbf7c07de721cb`

## AutoFill

The extension unlocks with Face ID or the passcode, reads the app-group store with the Keychain local key
(no Argon2id), and never syncs. Its only write is creating a passkey (one commit to the store, then it
republishes the QuickType identities). The list path checks the page URL with the desktop's match rules.
QuickType identities (published by the app after each sync, username + domain only) exist only for rows a
bare domain captures: `host`, `base_domain`, and `exact_origin` on https with the default port. `starts_with`,
http and non-default-port rows fill only through the list. Known gap: a QuickType fill gives the extension
only the stored identity, not the page URL, so iOS's own domain matching decides where it is offered.

## Safari extension

`SafariSave` (`app.localgatekeys.app.safari`) offers to save the logins you sign in with in Safari. Its web
resources in `SafariSave/Resources/` are generated, never edited by hand: run
`node browser-extension/build-safari-extension.cjs` (it writes both `SafariSave/Resources/` and the Mac's `SafariMac/Resources/`;
a node test fails when the committed folder differs from a fresh build). The shared content scripts are the desktop's, unchanged; `background-safari.js` keeps captures in
memory only and asks the native handler through `sendNativeMessage("app.localgatekeys.app", …)`.

`SafariWebExtensionHandler` passes each message to `SafariSaveService` (AppShared): `classify` against the
fingerprint index the app publishes, and `save` into a sealed inbox in the app group. It reads only
`safariIndexKey` and `safariInboxKey` (no Face ID), which live in the Safari extension's own Keychain group
(`LGK_SAFARI_KEYCHAIN_GROUP`; the extension is entitled to no other group, so it can never read the vault key);
it never opens the vault (only its committed revision number, for the free limit), syncs or opens a network
connection. At its next unlock the app asks before importing the saved logins waiting in the inbox (unread
captures expire after 7 days). Users turn it on in
Settings › Apps › Safari › Extensions and allow it on all websites.
