# Security and bug audit — 2026-10-18

Scope: `main` at 13008a7, the whole repo. Most attention went to code added since the
2026-10-14 audit (`b8a5794..HEAD`, 393 commits): the WebView UI and bridge, Wi-Fi / folder
sync and pairing, the iPhone app and AutoFill, the licence issuer, and CI. Six review passes
ran in parallel. I re-read the code behind the high finding and behind every WebView and
passkey finding before writing this report. The residual risks listed in
`SECURITY_AUDIT_2026-10-14.md` were not reported again.

**Tests**: Python suite passed (exit 0). Root `npm test` passed 183/183, and `webui` vitest
passed 108/108. Swift code was reviewed by reading it only: there is no Mac here, and CI has
no Swift job.

**Result**: 0 critical, 1 high, 13 medium, 19 low (33 distinct issues). None of them lets a
remote website take a credential with no user present. The most serious ones let a script in
the app window, or a person sitting at an unlocked PC, skip the master-password re-prompt.

**Accepted, not changed**

- Free devices can pool items through sync (`vault.py:1267`). The EULA allows this, and
  blocking sync merges would drop the user's own items.
- Licence revocation can still be undone offline by deleting both `revocations.json` and
  `license.revocations`. The built-in list in each build covers known leaks.
- Pairing has no Accept step before the reply: the iPhone waits about 5 s and sends no device
  name. The inviter shows Undo instead.

**Side effects and unverified points**

- An emergency lock waits for a long import or transaction to finish.
- Every legitimate join shows "added by another device" on the other PCs until it is confirmed.
- Exact-site logins appear in QuickType only when the new iPhone setting is on.
- Unverified: the M1 handler detach and the passkey wrapper rewrite in a real WebView2 or
  browser; all Swift changes and the macOS CI job (there is no Mac here, and CI is blocked by
  GitHub billing).

Confirmed = I traced the code myself. Plausible = the code supports it, but the timing or
the environment was not reproduced.

## High

| # | Where | Issue | Status |
|---|---|---|---|
| H1 | `app/controller.py:347`, `vault.py:2996` | Lock does not take `vault_lock`. `vault_lock`, `lock_emergency`, the auto-lock timer, the session monitor and app exit can zero the data key in place while a page or sync save is between its key check and `bytes(self._key)`. The vault would then be written under 32 zero bytes and become unreadable with the real password. Also, after a failed save, `transaction()` puts the plaintext payload back onto the locked session. | Plausible (narrow window) |

## Low

- `web/window.py:173`: pywebview's own NewWindowRequested handler still runs and passes any URI scheme to `webbrowser.open`. Set `OPEN_EXTERNAL_LINKS_IN_BROWSER = False`.
- `app/qr_import.py:127`: a lock-vs-scan race clears `_cancelled`, so the webcam can stay on for up to 90 s while locked.
- `browser-extension/webauthn-page.js:170`: the passkey wrapper lets any page fingerprint the extension and probe whether the vault is unlocked and holds a passkey for that site.
- `attachments.py:155`: "Open file" uses a deny-list. `.rdp`, `.iso`, `.vhd(x)`, macro-enabled Office files and similar still launch, with no Mark-of-the-Web.
- `app/icons.py:60`: when strict offline is off, favicons for every login are fetched at each unlock. That leaks which sites hold accounts and contradicts `SECURITY.md`.
- `vault.py:1267`: sync merges ignore the item limit, so several free devices can pool their items. This is by design according to the EULA; decide whether to keep it.
- `licensing.py:303`: revocation exists only in the cached `revocations.json`. Deleting the file un-revokes a licence, and MSIX builds never check it.
- `sync/transport.py:768`: the listener has one connection slot, so one idle LAN connection blocks sync and pairing. Enrollment frames take the sync gate.
- `sync/lan_sync.py:782`: the inviter accepts the first enrollment that proves the QR secret, with no confirmation. The 8-digit code is inside the QR and the copied text.
- `transfer.py:900`: transfer import ignores trash ids. An id that matches a trash row breaks restore and purge.
- `app/trash.py:114`: purge takes its lease after the confirm dialog, so the lease check does nothing.
- `app/schedule.py:108`: if starting the thread fails, `_running` stays True and scheduled backups stop silently.
- `app/settings.py:189`: `fill_and_sign_in` writes the vault flag before saving settings, so an `OSError` leaves the two out of step.
- `ios/AutoFill/PasskeyFlow.swift:195`: `erasePending` is not checked again before commit. An erase racing a passkey registration leaves a vault with no key.
- `ios/App/Sync/CoordinatedFolder.swift:105`: `Thread.sleep` busy-waits up to 30 s on a cooperative-pool thread.
- `.github/workflows/ci.yml:29,39`: actions are pinned to major tags, and an unpinned `pip` upgrade runs before the hash-locked install.
- `scripts/update_locks.ps1:24`: an unpinned `pip-tools` generates the hash locks.
