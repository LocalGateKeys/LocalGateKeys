# LocalGateKeys for Android

Status: Part A (the pure Kotlin core `lgk-core`) is done. Part B (the Compose app) is not started.
Design: `docs/superpowers/specs/2026-10-23-android-app-design.md`; plan: `docs/superpowers/plans/2026-10-23-android-core.md`.

## Layout

```
android/
  settings.gradle.kts, build.gradle.kts, gradle/libs.versions.toml, gradlew(.bat)
  lgk-core/
    src/main/kotlin/app/localgatekeys/core/
      json/       canonical JSON (Python-compatible floats, code point key order)
      primitives/ base64, hex, HKDF/AES-GCM (CryptoBox), Ed25519/X25519, casefold, ids
      crypto/     Argon2id interface and the Bouncy Castle implementation
      engine/     version vectors, merge, conflict copies
      records/    wrappers, normalisation, origins, URL matching, sync meta, licence
      group/      group key, sealed items, device view files
      keyring/    keyring parse, accept, join, member names
      lan/        pairing, enrollment, secure channel, LAN client
      sync/       folder sync and runner (join, run once)
      passkey/    passkey records, keys, authenticator data
      totp/       two-factor codes
      backup/     the LGKMBAK1 phone backup file
    src/test/kotlin/...   tests; support/ holds in-memory folder and store, deterministic randomness and the fixtures
```

`lgk-core` depends only on the Kotlin stdlib, Bouncy Castle and the JDK: no Android, coroutine or JSON library.
It is a port of the Swift `ios/LGKCore`; the shared vectors in `tests/vectors/sync` and `tests/vectors/backup`
are the contract and win over any behaviour.

## Running the tests

From the repository root (JDK 17 on `PATH`):

```
android/gradlew -p android :lgk-core:test
android/gradlew -p android :lgk-core:test --tests "*FolderSyncTest*"
```

Tests find the vectors through the system property `lgk.repoRoot` (the directory above `android/`, set in
`lgk-core/build.gradle.kts`) and fail, never skip, when a vector file is missing. Several tests run Argon2id at
production cost (128 MiB), so give the JVM memory.

## The round trip through the desktop

`FromAndroidTest` runs the phone flow: join the A/B/C sync group with the epoch-1 password, merge, create a web login,
edit a note, create a passkey, run again, and write a phone backup of the result. Randomness is one deterministic
stream, `DetRand("from-android")` (join, second run, then the backup salt and nonce), and the clock is fixed, so the
bytes are reproducible. The test compares them with the committed files:

- `tests/vectors/sync/from_android/keyring.lgkkeys`
- `tests/vectors/sync/from_android/devices/<device id>.lgksync`
- `tests/vectors/backup/from_android/backup.lgkm` (password `correct horse battery staple 42`)

To regenerate them (only when a format changes on purpose):

```
LGK_WRITE_FROM_ANDROID=1 android/gradlew -p android :lgk-core:test --tests "*FromAndroidTest*" --rerun
```

The desktop side reads them in `tests/test_sync_from_android.py` and `tests/test_backup_from_android.py`
(`.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider tests/test_sync_from_android.py tests/test_backup_from_android.py`).
The files are binary and byte-exact (`tests/vectors/** -text`, `*.lgksync` and `*.lgkm` binary in `.gitattributes`).

## Vendored tables

- `primitives/CasefoldTable.kt` is generated by `scripts/make_casefold_kotlin.py` from the `flat` table in
  `ios/LGKCore/Sources/LGKCore/Primitives/Casefold.swift` (Unicode 15.0.0, 1530 code points). Do not edit by hand.
- The Public Suffix List itself is not vendored in `lgk-core`: `records/PublicSuffixRules.kt` parses the list text the
  caller passes in (as the desktop does) and adds the desktop's local rule `*.web.core.windows.net`.
