The security model, in plain terms

What LocalGateKeys is designed to protect, and what it cannot protect.

How your vault is encrypted

A random 256-bit key encrypts the vault. That key is never stored as it is; it is wrapped (encrypted) separately by each way you can unlock, so changing your password does not mean re-encrypting everything, and a wrapper copied from another vault is rejected.

Vault encryption
AES-256-GCM with a fresh random nonce for every save
Master password
Argon2id, 64 MiB memory, 3 passes, parallelism 4, random salt per wrapper
Recovery phrase
Optional 24-word BIP39 phrase (256 bits), expanded with HKDF-SHA256
Windows Hello
Wraps the vault key, never the master password
Backups and transfers
Argon2id and AES-256-GCM with the parameters stored in the authenticated header
Device sync
A random group key, handed to each device with X25519 and HKDF-SHA256 and, for a cloud folder, also wrapped by your sync password with Argon2id; every record sealed with AES-256-GCM and bound to its item, version and key epoch; every device file bound to the device that wrote it
Passkeys
ES256 (P-256) keys kept inside the encrypted vault; the app builds the signed data from the origin the browser reports, never from the page
Writes to disk
Temporary file, flush, then atomic replace, so a crash cannot leave half a vault

Designed to protect against

  • Someone who copies your vault file or a backup and does not know your master password
  • A website getting logins or passkeys saved for a different website
  • Another program on your PC talking to LocalGateKeys without the session secret it hands to its own browser helper
  • Filling a desktop app that has been swapped, updated or changed since you bound it
  • Passwords sitting unencrypted on disk
  • Forms being submitted without you
  • Your cloud provider reading synced data: it only stores ciphertext

Not able to protect against

  • Malware, or anyone with administrator control, already running on your PC
  • A compromised browser, Windows installation or dependency
  • A website you deliberately fill a password into
  • Someone using your PC while the vault is unlocked
  • Phishing inside a genuine app that shows attacker-controlled content
  • Losing your vault, your backups and your master password with no recovery phrase: nobody, including us, can open it

Things LocalGateKeys never does

Some ways of filling passwords are indistinguishable from spyware, so they are ruled out by design. LocalGateKeys contains no:

  • keyboard hooks or keystroke recording
  • clipboard monitoring
  • screen reading or OCR to find credentials
  • scanning of other programs' memory
  • decryption of your browser's saved-password database
  • code injection into other programs or games
  • submitting a sign-in you did not start

The network, honestly

There is no LocalGateKeys account and no server that holds vaults. The app connects to the internet in only these cases:

  • Update checks. When you choose Check for updates, the app downloads one small file and verifies its signature with a key built into the app. It never downloads or runs an installer by itself.
  • Licence revocation list. Together with each update check, the app downloads a signed list of refunded licences and checks your licence against it on your PC. It sends nothing about your licence.
  • Website icons. To show a site's icon, the app downloads it from that site's own address. No username, password or vault data is sent, but each download tells that site, and anyone watching the network, that your vault has an account there. This is off by default and only happens if you turn on "Show website icons" in Settings; strict offline mode blocks it.
  • Breach checks, if you turn them on. When you start a check, the app sends the first five characters of each password's SHA-1 hash to Have I Been Pwned. The service sees your IP address, never the password, the full hash, the username or the website.
  • Sync, if you set it up. Over your home network, devices talk to each other directly. Through a cloud folder, your cloud-drive app does the uploading.

Strict offline mode is on by default. It blocks background internet requests, website icons and breach checks, and an update check asks you first. The privacy policy lists exactly what our servers see when you do check for updates.

Known limitations

  • The master password is moved into a wipeable buffer as soon as it reaches the app and is erased when the operation that needed it finishes. The page you type it into runs in Microsoft Edge WebView2, and the hand-off from that page to the app makes a short-lived copy; neither copy can be erased by the app.
  • The camera unlock is a convenience check, not certified protection against photos or masks. Windows Hello is the stronger choice.
  • Windows app fill does not work with programs running as administrator, custom-drawn game interfaces, or embedded web views it cannot verify.
  • The vault detects being rolled back to an older copy. If you use sync, your other devices also remember how new your vault was, so deleting the vault and its anchor file together is caught at the next sync (Windows PCs for now; the iPhone, Mac and Android apps follow). Without sync, someone who can replace both files can still defeat the check.
  • Passkeys work in Chrome and Edge only, and only for the page itself: a sign-in inside another site's frame uses the browser's own passkey dialog. If a site cancels after you approve a new passkey, the passkey may stay in your vault; delete it in the app.
